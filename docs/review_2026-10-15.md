# Response to the October 15 review

The review analysed a run made outside this repository: an annual dataset, the revised 35/45/20 proposal, an SPY/IEF/BIL mapping and ST1–ST4 definitions. None of those inputs are committed here, so its specific numbers (for example 99.53% payment success, or BVAR 95% Treasury coverage of 81.7%) cannot be reproduced from this repository. Every *mechanism* the review identified has been addressed in the engine, as set out below. Order follows the review's priorities.

## 1. Forecast calibration and data workflow (first priority)

| finding | change | still open |
|---|---|---|
| both models fail validation; uncertainty under-represented | third candidate **`bvar_t`**: BVAR(1) with Student-t innovations, fitted by a Gibbs sampler (`forecast/bvar.py`) and scored by the same validator | on the synthetic fixture it fixes cash undercoverage (5-year 95% cash coverage 95%) but **overcovers** 5-year equity (about 96% at the 80% level) and passes only 2 of 3 Monte Carlo replicates. The outcome remains `NO_VALIDATED_FORECAST`, and nothing was tuned to pass |
| a pass can depend on the seed | **seed-stability rule**: a PASS must be reproduced in `seed_replicates` (3) independent validation replicates, otherwise `UNSTABLE_PASS` (not validated) | none |
| fallback used fixed parameters with no uncertainty | the assumption fallback now draws parameters around the stated values (NIW with `kappa`, `nu` in years-equivalent, configurable). It is still labelled `CONDITIONAL_SCENARIO_NOT_EVIDENCE`, and the headline says **"conditional on assumed parameters: more paths make it more precise, not more true"** | the centre of the distribution is still an assumption |
| annual data could not run the monthly block bootstrap | `bootstrap.mode: auto` falls back to a **synchronised annual block bootstrap** (`block_years`, never crossing gaps) | the annual bootstrap resamples few distinct blocks from short histories (stated limitation) |
| revised data, not publication vintages | optional **`vintage_date`** column (annual or monthly). Validation rebuilds each origin's training data exactly as published before that origin (`data/vintage.py`). Without it, the report states that revision look-ahead is possible | actual vintage data (for example ALFRED/real-time CPI) must be obtained |
| outcomes already inspected; a fresh seed is not an untouched test | the frozen evaluation record now reports **`untouched_scored_origins`**: outcomes published after the freeze date, the only genuinely out-of-sample tests. The count is 0 without a freeze | genuinely new outcomes accrue only as data are published after the freeze |

## 2. Risk metrics

| finding | change |
|---|---|
| $50,000 missed with zero forced sales | new **`p_payment_not_reserve_funded`**: any payment not covered by scheduled reserve cash, whether by a sale or by a shortfall. Also funding-source shares (reserve / sales / unpaid) and `p_missed_without_any_sale`. It is a hard rule in the demo policy, and a **soft (reported) rule in the readiness policy**, because section 6 thresholds stay frozen until the risk team adopts it |
| annual observations miss within-year losses and breaches | **within-year diagnostic** (`risk/intrayear.py`): a joint Brownian bridge between simulated annual endpoints reports intra-year drawdown versus the annual-endpoint drawdown, and the within-year maximum equity share. It is **reported separately and never feeds the frozen annual gate**. Concentration can check the drifted state when the policy accepts the bridge (`drift_check: bridge`); the readiness policy keeps `required`, which needs a genuine sub-annual simulation from data |

## 3. Reserve implementation

| finding | change | still open |
|---|---|---|
| 2033 curve assumed separately from simulated returns | per-path curves (`PathCurves`). A sensitivity case shifts each path's 2033 curve with its own simulated 2032 cash return (`path_linked_curve_beta`); it is labelled an assumption, not a validated rate model | a jointly estimated term-structure model |
| maturities, securities, prices, lot sizes not reconciled | **`policies/reserve_instruments.py`**: builds a dedicated ladder from dated quotes (maturity, coupon, clean price + accrued interest, settlement, whole lots), holds early cash at 0%, and reports cost, excess cash and unmatched dates. The pipeline runs it when `data.reserve_instruments_file` is set | real quotes; settlement at the actual 2033 date |

## 4. Proposed ETFs

| finding | change | still open |
|---|---|---|
| mapping does not change simulated returns or mechanics | an optional `expense_ratio` holdings column now **enters simulated costs** per sleeve. An optional `instrument_returns_file` reports each sleeve's **tracking error, correlation and beta versus the simulated proxy**. The report says plainly that the simulation still uses the broad sleeve proxies and that a fund portfolio is an implementation proposal, not an engine-optimised result | simulating instrument returns directly; lot and trading mechanics for the competition account |

## 5. Stress and sensitivity gaps

| finding | change |
|---|---|
| extra-fee stress excluded reserve assets yet could pass | a reserve holding fee now exists in the simulator, paid from retained assets, then reserve cash, then by selling reserve positions. `s7_higher_costs` adds 0.25%/yr on reserve value, and every stress row reports **what it actually touches** (`scope`) |
| sensitivity covered only the original baseline | `sensitivity.candidates: all_validated` runs every validated candidate (any revised proposal included once it is in the candidate file), plus the path-linked curve case |

## Not changed, deliberately

- No tolerance was widened and no prior was retuned to make a model pass.
- The section 6 thresholds in `risk_policy_readiness.yaml` are unchanged; the new reserve-coverage rule is soft there.
- No frontend work, and no change to the simulation count.
